## 2. 受注 API（IF-003）

ベース URL：`http://<ホスト>:8000`。要求・応答とも `application/json`（UTF-8）。起動中は `/docs` に OpenAPI の画面が表示される。

### 2.1 エンドポイント一覧

| メソッド | パス | 用途 | 主な応答 |
|---|---|---|---|
| GET | `/health` | 死活確認 | 200 |
| POST | `/orders` | 受注を登録する（抽出済みの項目） | 201 登録 ／ 200 重複 ／ 422 |
| GET | `/orders` | 受注一覧（`month`・`customer`・`limit`） | 200 ／ 422 |
| GET | `/reports/monthly` | 月次集計（`month` 必須、`group_by`） | 200 ／ 422 |
| POST | `/intake/email` | メールを受け取り、抽出→検証→登録を一度に行う | 201 ／ 200 重複 ／ 422 ／ 413 |
| POST | `/extract` | 抽出だけを行う（登録しない）。`mode=rule\|llm\|auto` | 200 ／ 422 |
| POST | `/rejections` | 取込エラーを記録する（n8n の検証不合格） | 201 ／ 422 |
| GET | `/rejections` | 取込エラー一覧 | 200 |

### 2.2 POST /orders

要求の項目は `app/order_schema.json`（JSON スキーマ）で定義する。

| 項目 | 型 | 必須 | 規則 |
|---|---|---|---|
| message_id | 文字列 | ○ | 3〜255 文字、空白なし。メールの Message-ID |
| customer_name | 文字列 | ○ | 1〜100 文字。登録時に NFKC で全角・半角をそろえる |
| product | 文字列 | ○ | 1〜100 文字。同上 |
| quantity | 整数 | ○ | 1〜100,000 |
| due_date | 文字列 | ○ | `YYYY-MM-DD`。実在する日付で、受信日以降 |
| received_at | 文字列 | — | ISO 8601。タイムゾーン付きは JST に変換。省略時は現在時刻 |
| extractor | 文字列 | — | `llm` ／ `rule` ／ `manual`（既定 `manual`） |

要求例：

```json
{
  "message_id": "<20261102.0915.a1@mail.example.com>",
  "customer_name": "サンプル商事株式会社",
  "product": "A4コピー用紙（500枚×5冊）",
  "quantity": 20,
  "due_date": "2026-11-10",
  "received_at": "2026-11-02T09:15:00+09:00",
  "extractor": "llm"
}
```

応答例（201 登録。重複時は 200 で `"duplicate": true` と既存の受注）：

```json
{
  "duplicate": false,
  "order": {
    "id": 1,
    "message_id": "<20261102.0915.a1@mail.example.com>",
    "customer_name": "サンプル商事株式会社",
    "product": "A4コピー用紙(500枚×5冊)",
    "quantity": 20,
    "due_date": "2026-11-10",
    "received_at": "2026-11-02T09:15:00",
    "extractor": "llm",
    "created_at": "2026-11-15T17:58:40"
  }
}
```

応答例（422 検証エラー。同時に取込エラーとして記録される）：

```json
{"detail": {"errors": [{"field": "数量", "message": "必須項目がありません"}]}}
```

### 2.3 POST /intake/email

| 項目 | 型 | 必須 | 規則 |
|---|---|---|---|
| message_id | 文字列 | ○ | 空白を含まない 3〜255 文字 |
| body | 文字列 | ○ | メール本文。20,000 文字まで |
| subject | 文字列 | — | 件名 |
| received_at | 文字列 | — | ISO 8601 |
| from | 文字列 | — | 差出人（保存しない） |

抽出方式は環境変数 `EXTRACTOR_MODE`（`rule` 既定 ／ `llm` ／ `auto`）で決まる。登録済みの Message-ID は抽出前に 200 で返し、LLM を呼び直さない。

### 2.4 GET /reports/monthly

| パラメータ | 必須 | 値 |
|---|---|---|
| month | ○ | `YYYY-MM` |
| group_by | — | `customer_product`（既定）／ `customer` ／ `product` |

応答例：

```json
{
  "month": "2026-11",
  "group_by": "customer",
  "rows": [
    {"customer_name": "サンプル商事株式会社", "product": null, "order_count": 2, "total_quantity": 35}
  ],
  "total": {"order_count": 2, "total_quantity": 35}
}
```

### 2.5 エラーコード

| ID | HTTP | 発生箇所 | 条件 | 呼び出し側の対応 |
|---|---|---|---|---|
| ERR-001 | 422 | POST /orders、/intake/email | スキーマ・業務ルールの検証エラー。`detail.errors` に項目と理由 | 再送しない。取込エラー一覧で内容を確認し、手で登録する |
| ERR-002 | 413 | POST /intake/email、/extract | 本文が 20,000 文字を超える | 本文を確認する（添付の貼り付け等） |
| ERR-003 | 422 | GET 系、/rejections | パラメータの形式誤り（`month` 等） | 呼び出し側の不具合として修正 |
| ERR-004 | 500 | 全般 | 想定外のエラー（DB ファイルに書けない等） | ログを確認。登録系は再送してよい（冪等） |

## 3. n8n → 受注 API の連携（IF-001〜IF-003）

### 3.1 Webhook の受け口（IF-001）

| 項目 | 内容 |
|---|---|
| URL | `http://<n8n>:5678/webhook/order-intake`（POST） |
| 要求 | 2.3 と同じ JSON（message_id・subject・body・received_at） |
| 応答 | 登録・重複は API の応答をそのまま返す。不合格・障害は下表 |

| ID | HTTP | 段階 | 内容 |
|---|---|---|---|
| ERR-005 | 422 | n8n のスキーマ検証 | `{"stage":"validation","errors":[...]}`。API の `/rejections` にも記録 |
| ERR-006 | 422 | API が受け付けなかった | API が状態コード 300 以上を返した場合（主に検証の 422。例：納期が受信日より前）。API の 500 なども同じく 422 で返し、元の状態コードは `status` に入る：`{"stage":"api","status":<API の状態コード>,"detail":...}` |
| ERR-007 | 503 | API に接続できない | 3 回再試行（2 秒間隔）後に `{"stage":"api","message":...}` |
| ERR-008 | — | LLM の失敗 | エラーにせず API の規則抽出（`POST /extract`）に切り替える |

### 3.2 Gmail から直接取り込む場合

Webhook受信ノードを Gmail Trigger ノードに差し替え、「LLM依頼の作成」ノード先頭の `src` を次の対応で組み替える。応答ノード（Respond to Webhook）は不要になるため、失敗の通知はメール・チャットへの送信に置き換える。

| 受注 API の項目 | Gmail Trigger の出力（簡易表示を切った場合） |
|---|---|
| message_id | メールヘッダの Message-ID |
| subject | 件名 |
| body | 本文（テキスト） |
| received_at | 受信日時 |

Gmail の出力項目名は n8n のバージョンで異なるため、差し替え時に実データで確認する。

### 3.3 再試行と冪等性

- 「受注登録」ノードは通信失敗時だけ 3 回再試行する。4xx は応答として受け取り（neverError）、再試行しない
- API は Message-ID の一意制約で重複を防ぐため、再試行・再実行で二重登録にならない（ADR-0003）

## 4. 月次集計 CSV（IF-004）

| 項目 | 内容 |
|---|---|
| ファイル名 | `monthly_orders_YYYY-MM.csv`（帳票マクロはファイル名から集計月を読む） |
| 文字コード | UTF-8（BOM 付き） |
| 改行 | CRLF |
| 区切り | カンマ。カンマ・ダブルクォートを含む値はダブルクォートで囲み、`"` は `""` |
| 見出し行 | あり（1 行目固定） |
| 並び順 | 顧客名、商品の昇順（帳票マクロはこの並びで小計を入れる） |
| 0 件の月 | 見出し行だけを出力する |
| 数式の無害化 | 顧客名・商品が `=` `+` `-` `@` タブ・改行で始まる場合、先頭に `'` を付ける（表計算ソフトで数式として動かないように） |

| No | 項目名 | 型 | 例 |
|---|---|---|---|
| 1 | 集計月 | 文字列（YYYY-MM） | 2026-11 |
| 2 | 顧客名 | 文字列 | サンプル商事株式会社 |
| 3 | 商品 | 文字列 | A4コピー用紙(500枚×5冊) |
| 4 | 件数 | 整数 | 2 |
| 5 | 数量合計 | 整数 | 35 |
