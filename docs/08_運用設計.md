## 1. ジョブ一覧

| ジョブ名 | 機能 | 起動 | 実行内容 | 所要時間の目安 | 失敗時 |
|---|---|---|---|---|---|
| 受注メール取込 | FN-001 | メール受信ごと（Webhook） | 抽出・検証・登録 | 規則抽出は 1 秒未満、LLM はモデルと PC 性能に依存（本検証の環境では 1 通数秒） | 応答コードと n8n の実行履歴を確認 |
| 月次集計 | FN-008 | 毎月 1 日 6:00（タスクスケジューラ） | 前月分の CSV・xlsx を出力 | 数秒 | 終了コード 0 以外。ログを確認して再実行 |
| 月次帳票作成 | FN-009 | 毎月 1 日の業務開始後（担当者が手動） | CSV から帳票を作成 | 数秒 | メッセージの内容に従う |
| DB バックアップ | — | 毎日 22:00 | DB ファイルの複製 | 数秒 | 次回実行で再取得 |

### 1.1 月次集計の登録例

Windows（タスクスケジューラ）：

```
schtasks /Create /TN "OrderIntake\MonthlyReport" /SC MONTHLY /D 1 /ST 06:00 ^
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\apps\order-intake-system\batch\run_monthly.ps1"
```

Linux（cron、同じ PC で API が動いている場合）：

```
0 6 1 * * cd /opt/order-intake-system && .venv/bin/python -m batch.monthly_report >> output/monthly.log 2>&1
```

## 2. 日々の確認

| 確認内容 | 方法 | 頻度 |
|---|---|---|
| 取込エラーの有無 | `GET /rejections` で前日以降の記録を確認し、元のメールを見て手で登録する | 毎朝 |
| API の稼働 | `GET /health`（Docker では healthcheck） | 常時 |
| n8n の失敗実行 | n8n の実行履歴で Error を絞り込む | 毎朝 |

## 3. 障害対応表

| 事象 | 想定原因 | 確認 | 対応 | 再実行 |
|---|---|---|---|---|
| Webhook が 503（ERR-007） | API の停止・接続先の誤り | `GET /health`、n8n「設定」の api_url | API を起動・接続先を修正 | 同じメールを再送してよい（重複しない） |
| 取込エラーが急に増えた | 取引先のメール書式の変更、LLM の停止 | 取込エラーの理由、API ログの LLM 切替 | 規則の項目名を追加、LLM を再起動 | 元のメールを再送 |
| すべて extractor=rule になる | LLM の停止・モデル未取得 | API ログの「LLM fallback」、Ollama の `/api/tags` | LLM を起動・モデルを取得 | 不要（登録済み） |
| 月次集計が終了コード 1 | API の停止・DB ファイルがない | バッチのログ | API を起動、または `--db` で DB を直接指定 | `run_monthly.ps1 -Month YYYY-MM` |
| 帳票マクロが「見出しが想定と異なります」 | 別のファイル・古い形式の CSV を選んだ | ファイル名と 1 行目 | 正しい CSV を選ぶ | マクロを再実行（同じ月は置き換え） |
| 集計の数字が合わない | 顧客名・商品名の表記揺れ | `GET /orders?month=` で明細を確認 | マスタの名寄せ（対象外の運用作業） | 名寄せ後に月次集計を再実行 |

## 4. バックアップと戻し方

| 対象 | 方法 | 保管 | 戻し方 |
|---|---|---|---|
| DB（SQLite） | 毎日 `sqlite3 data/orders.db ".backup backup/orders_YYYYMMDD.db"`（書き込み中でも整合した複製が取れる） | 30 日分 | API を停止し、複製を `data/orders.db` に置き換えて起動 |
| DB（SQL Server 移行後） | 完全バックアップ（日次）＋ログバックアップ | 運用規程に従う | 時点復旧 |
| n8n フロー | `n8n/order-intake.json` をリポジトリで管理 | Git | n8n に取り込み直す |
| 月次 CSV・xlsx・帳票 | 共有フォルダに月ごとに保存 | 7 年（帳簿書類の保存に合わせる想定。期間は社内規程で確認） | — |

Docker で動かしている場合、DB はボリューム `order-data` の中にある。`docker compose cp api:/data/orders.db ./backup/` で取り出せる。

## 5. 設定値の管理

| 設定 | 置き場所 | 備考 |
|---|---|---|
| DB_PATH、EXTRACTOR_MODE、OLLAMA_URL、OLLAMA_MODEL、LOG_LEVEL | 環境変数（docker-compose.yml） | 秘匿値ではない |
| n8n の接続先 | n8n「設定」ノード | 外部の LLM サービスを使う場合、API キーは n8n の資格情報に登録し、フローの JSON には書かない |
