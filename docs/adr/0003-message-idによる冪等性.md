## 背景

同じ注文メールは、n8n の再実行、通信エラー時の再送、メールサーバ側の重複配信などで複数回届きうる。内容（顧客・商品・数量）の一致で重複を判断すると、同じ内容の別注文（毎月の定期注文など）を誤って捨ててしまう。

## 決定

- メールヘッダの Message-ID を受注の一意キーとし、データベースに一意制約を付ける
- 登録前の存在確認（SELECT してから INSERT）には頼らず、INSERT 時の一意制約違反を捕まえて「登録済み」と判断する。同時に 2 件届いた場合も 1 件しか登録されない
- 重複時は HTTP 200 と既存の受注を返す（`duplicate: true`）。初回は HTTP 201。呼び出し側はどちらも成功として扱える
- このため n8n の API 呼び出しは再試行を有効にできる

## 結果

- 再送・再実行を気にせず取り込みを繰り返せる
- Message-ID を持たない経路（手入力等）では、呼び出し側が一意な ID を採番して渡す必要がある
