## 背景

受注件数は月に数百件程度の想定で、最初からデータベースサーバを用意するほどの規模ではない。一方、利用部門が増えた場合や他システムと連携する場合は、社内標準の SQL Server に載せ替える可能性がある。

## 決定

- 開始時は SQLite（ファイル 1 つ）を使う
- SQL は標準 SQL の範囲で書く。月の絞り込みは `received_at >= '2026-11-01' AND received_at < '2026-12-01'` の範囲条件にし、`strftime` などの方言関数を使わない
- 日時は ISO 8601 の文字列で保存する（SQL Server では `DATETIME2` に対応）
- SQL Server 用の DDL（`sql/schema_sqlserver.sql`）を併記し、型・制約の対応を 04_テーブル定義書.md に記載する
- 一意制約違反の検出は、データベースごとの例外をデータアクセス層の 1 か所で吸収する

## 結果

- 導入時の手間がなく、テストも一時ファイルで完結する
- 同時書き込みが多い場合は SQLite の書き込みロックが制約になる。その時点で SQL Server へ移行する
- 移行時の変更点はデータアクセス層（`app/db.py`）の接続部分と、`INSERT` 後の採番値の取り方（`OUTPUT INSERTED.id`）に限られる
