## 背景

メールの書き方は取引先ごとに異なり、項目名のない文章（「〇〇を 20 箱、今月 25 日までに」）にも対応したい。LLM はこの揺れに強いが、停止・タイムアウト・出力形式の崩れが起こりうる。LLM の障害で受注の取り込みが止まると業務に直接影響する。

## 決定

- 抽出は「LLM」と「規則（正規表現）」の 2 方式を用意する
- n8n では LLM の呼び出しが失敗した場合、API の規則抽出（`POST /extract`）に切り替える
- API 単体では環境変数 `EXTRACTOR_MODE` で `rule`（既定）／`llm`／`auto`（LLM を試し、失敗・不正なら規則）を選べる
- どちらの方式の結果も、同じ JSON スキーマで検証してから登録する。抽出方式は受注に記録する（`extractor` 列）

## 結果

- LLM・API キーがない環境でも、システム全体と自動テストが動く
- 規則抽出は項目名のある定型的なメールに強く、文章形式のメールでは取り出せない項目が出る。その場合は検証で不合格となり、取込エラーとして記録されるため、黙って誤登録されることはない
